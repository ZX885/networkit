# NetworkIt — дизайн-система

Источник: `networkit-backend/web/index.html` (`:root` строки 33–62, тёмная тема 2528–2812, медиа-запросы 272–3972). Связанные документы: `docs/SPEC.md`, `docs/ARCHITECTURE.md`. Значения контраста ниже — **оценки по формуле WCAG**, перед релизом проверить инструментом (Lighthouse / DevTools) [нужна проверка в рантайме].

## 1. Принципы

1. Все цвета, отступы, радиусы, тени, z-index — **только через CSS-переменные** (`frontend/src/styles/tokens.css`). Жёстких `#hex`, `px`-цветов и `style="color:…"` в компонентах нет.
2. Стили компонентов — CSS Modules (`Name.module.css`) рядом с компонентом; токены глобальные.
3. Тёмная тема — это **только другой набор значений переменных**. Никаких `body.dark .класс {…}` (в legacy их ~60 штук, большинство лишние).
4. Mobile-first: базовые стили для телефона, расширения через `@media (min-width: …)`.
5. Доступность — часть компонента, а не «доработка» (фокус, роли, подписи, контраст, reduced-motion).
6. Не переносим из legacy: мёртвые стили (online-status, suggest, completeness, onboarding, notifications — ANALYSIS §B), дубли медиа-запросов.

## 8. Правила тёмной темы

1. Переключатель — атрибут `data-theme="light|dark"` на `<html>`; **значение всегда конкретное**: режим `system` разрешается в JS (`matchMedia('(prefers-color-scheme: dark)')`) и обновляется при смене системной темы. В `tokens.css` только два блока: `:root { …светлые… }` и `[data-theme="dark"] { …тёмные… }` (без дублирования под media-query).
2. До первой отрисовки `public/theme-init.js` читает `localStorage['nk_theme']` (в `try/catch`: `light|dark|system`, по умолчанию `system`) и ставит атрибут — нет вспышки неверной темы. Выбор пользователя хранится только там.
3. `color-scheme: light dark` на `:root` — родные элементы (скроллбары, `select`, `input[type=date]`) получают верную тему.
4. В компонентах — только токены. Запрещено: `body.dark …`, `[data-theme] .x` в модулях, `#hex`/`rgb()` вне `tokens.css`, `style={{ color: … }}`. Проверка: `grep -rnE "#[0-9a-fA-F]{3,8}|rgba?\(" src --include=*.css` должен находить только `tokens.css`.
5. Тени и подложки в тёмной теме — отдельные значения токенов (§2–3), а не «прозрачнее».
6. Текст в primary-цвете — через `--primary-text`; фон кнопок — `--primary` + `--on-primary`.
7. Изображения: аватары не инвертируются; логотип использует `--primary` и `--on-primary`.
8. Нужно проверять обе темы на каждом экране (чек-лист этапа 12): контраст текста ≥4.5:1, крупного/иконок ≥3:1, фокус виден.

## 9. Glassmorphism

В legacy стекло есть в одном месте: верхняя панель `#nav` — `background: rgba(255,255,255,.92)` + `backdrop-filter: blur(12px)` (index.html:502–503), в тёмной теме `rgba(10,10,10,.95)` (2553). Это и есть точка отсчёта.

### 9.1 Токены
| Токен | Светлая | Тёмная |
|---|---|---|
| `--glass-bg` | `rgba(255,255,255,.88)` | `rgba(17,17,17,.88)` |
| `--glass-bg-strong` | `rgba(255,255,255,.96)` | `rgba(17,17,17,.96)` |
| `--glass-border` | `rgba(17,24,39,.08)` | `rgba(255,255,255,.08)` |
| `--glass-blur` | `12px` | `12px` |
| `--glass-saturate` | `1.4` (необязательно) | `1.2` |
| `--glass-shadow` | `var(--shadow-3)` | `var(--shadow-3)` |

Прозрачность ≥ .85 для панелей с текстом — читаемость не зависит от того, что под стеклом.

### 9.2 Где применять (максимум 1–2 стеклянных слоя в окне одновременно)
- верхняя панель лендинга (`TopNav`) — как в legacy;
- мобильная шапка приложения с кнопкой меню (sticky);
- выпадающая история поиска и меню (маленькие плавающие панели);
- тост;
- заголовок открытого чата (sticky поверх прокручиваемых сообщений) — по желанию.

### 9.3 Где НЕ применять
- карточки профилей и любые элементы в длинных списках (десятки `backdrop-filter` в одной прокрутке);
- формы, поля ввода, таблицы, длинный текст (био, сообщения), пузыри чата;
- модальную подложку на всю страницу (используем плоский `--overlay`, без blur);
- элементы поверх однотонного фона (эффекта нет, а стоимость есть);
- вложенные стеклянные элементы (`backdrop-filter` внутри `backdrop-filter`);
- анимируемые элементы (не анимировать `blur`, не включать `will-change: backdrop-filter`).

### 9.4 Эскиз реализации и запасной вариант
```css
.glass {
  background: var(--glass-bg);
  border: 1px solid var(--glass-border);
  -webkit-backdrop-filter: blur(var(--glass-blur)) saturate(var(--glass-saturate));
  backdrop-filter: blur(var(--glass-blur)) saturate(var(--glass-saturate));
}
/* нет поддержки backdrop-filter → плотная заливка */
@supports not ((backdrop-filter: blur(1px)) or (-webkit-backdrop-filter: blur(1px))) {
  .glass { background: var(--glass-bg-strong); }
}
/* пользователь просит меньше прозрачности / больше контраста */
@media (prefers-reduced-transparency: reduce), (prefers-contrast: more) {
  .glass { background: var(--surface); -webkit-backdrop-filter: none; backdrop-filter: none; border-color: var(--border-strong); }
}
```
Префикс `-webkit-` пишем вручную (в проекте нет autoprefixer в списке библиотек). Поддержку `prefers-reduced-transparency` проверить в целевых браузерах [нужна проверка в рантайме]; без неё остаётся правило `@supports` и `prefers-contrast`.

### 9.5 Доступность и производительность
- Контраст текста считать для худшего фона под стеклом (белая страница + самый тёмный/яркий контент) при минимальной непрозрачности; границу (`--glass-border`) не использовать как единственный индикатор.
- `backdrop-filter` создаёт отдельный композитный слой, дорог на слабых телефонах и при прокрутке контента позади; поэтому — малые фиксированные элементы, blur ≤12px, не более двух слоёв.
- Не использовать стекло для индикации состояния (ошибка/успех) — только как оформление.
- Проверить на бюджетном Android и в Safari (iOS) при прокрутке списка поиска под sticky-шапкой; если подтормаживает — шапка получает `--glass-bg-strong` без blur.

## 10. Компоненты `components/ui/`

| **Avatar** | `size`: `xs` 32, `sm` 38, `md` 44, `lg` 72, `xl` 80; `src`, `name` (инициалы, цвет по хэшу `username`) | загрузка, ошибка загрузки → инициалы | `alt=""` если рядом имя, иначе `alt="Name"`; `loading="lazy"` в списках |
| **Card** | `variant`: `plain`, `interactive` (hover: тень + подъём 2px, фокус), `glass` (только §9.2); `padding` | default, hover, focus-within | интерактивная — целиком ссылка/кнопка с одним основным действием |
| **Modal** | `title`, `description`, `actions`; на `<600px` — bottom sheet | открыта/закрыта, loading кнопок | `role="dialog"`, `aria-modal`, `aria-labelledby`; ловушка фокуса, Esc, возврат фокуса, блок прокрутки фона; рендер в portal |
| **Toast** | `tone`: `info`, `success`, `error`; автозакрытие 4 с (ошибки — 6 с), пауза при наведении | появление/исчезновение (без анимации при reduced-motion) | контейнер `aria-live="polite"` (`assertive` для ошибок), не перекрывает поля |
| **Alert** (inline, legacy `amsg`) | `tone`: `error`, `success`, `info`, `warning` | — | `role="alert"` для ошибок |
| **Spinner / Skeleton** | `size`; skeleton-карточка и строка | — | `role="status"` + скрытый текст «Loading…» |
| **EmptyState** | `icon`, `title`, `text`, `action` | — | заголовок `<h2>`/`<h3>` по контексту |
| **Pagination** | `page`, `pageCount`, окно из 5 страниц + первая/последняя (не все страницы, как в legacy) | текущая, disabled prev/next | `<nav aria-label>`, `aria-current="page"` |
| **Tabs** | `value`, `items`; вариант «вертикальные» (настройки), «сегменты» (Chats / Requests / Sent) | selected, focus | `role="tablist/tab/tabpanel"`, стрелки |
| **StepProgress** | `current`, `total`, `labels` (мастер регистрации: 8 шагов) | done / current / todo | `role="progressbar"` + `aria-valuenow`, текст «Step 3 of 8» |
| **PasswordStrength** | `value` → weak/medium/strong | — | текстовая метка (не только цвет); исправляет F-код класса `.pb` без стилей |
| **Icon** | `name`, `size` (1em) | — | декоративные `aria-hidden="true"`; решение по источнику иконок — Q-D1 |
| **Spacer/Container/Stack** (layout-примитивы) | `gap` из шкалы | — | вместо inline-стилей `margin` |

Компоненты уровня `layout/`: **TopNav** (лендинг; стекло), **AppLayout** + **Sidebar** (≥900 px постоянный; <900 — выезжающая панель с подложкой и `inert` для фона, закрытие по Esc/клику), **PageHeader**, **Footer**. Предметные компоненты (`ProfileCard`, `ConversationList`, `ChatWindow`…) собираются из `ui/` и описываются в коде, а не здесь.

## 11. Чек-лист перед закрытием этапа 12

- Контраст: текст ≥4.5:1, крупный ≥3:1, иконки/границы управляющих элементов ≥3:1 — в обеих темах.
- Клавиатура: все действия достижимы Tab/Enter/Space/Esc, порядок фокуса логичен, фокус виден; ссылки — `<a href>`, действия — `<button>`.
- Масштаб: `viewport` без `maximum-scale` (в legacy стояло `maximum-scale=1.0`, WCAG 1.4.4), текст масштабируется до 200%.
- `prefers-reduced-motion`, `prefers-color-scheme`, `prefers-contrast`, `prefers-reduced-transparency` учтены.
- Размеры касания ≥40 px; нет горизонтального скролла на 360 px.
- Lighthouse Accessibility ≥90 и Performance приемлемая на эмуляции среднего телефона; стеклянных слоёв ≤2 в окне.
